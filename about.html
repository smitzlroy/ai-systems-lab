About this learning project

AI Systems Lab is a standalone, static learning site. It uses original explanations, illustrative browser simulations and links to public sources. It is not affiliated with the referenced providers and does not reproduce their courses.

What is available

Eight inference lessons, interactive labs, animated diagrams and a glossary. Six additional topic areas have curriculum outlines and curated resources, not completed interactive lessons. The research library was reviewed on 2 November 2026; this is not a claim that every course was completed or every existing example was revalidated.

The Applied scenarios section connects the theory to five fictional workflows: document processing, grounded retrieval, permission-aware assistance, voice latency and guardrail evaluation. Each includes a diagram, a synthetic dataset, worked interpretation, a decision checkpoint and an evaluation checklist. Related lessons and topic outlines link back to these scenarios.

Local use

Open index.html in a current browser. No installation, build, account or API key is needed. Lesson progress, theme and the last selected lesson use browser localStorage under the existing inference-learning-lab keys. Moving to a website creates a different storage origin; local-file progress will not migrate automatically. Storage failures are shown in the page.

Publishing on GitHub Pages

This independent project is hosted on GitHub Pages, with its reviewed source in a separate repository. Asset paths are relative and no server-side code is required.

  1. Review all files for confidential, customer-derived and personal content, including examples, comments, metadata and source links. Do not copy a career workspace, private source documents or their Git history into this project.
  2. Recheck model names, prices, service terms and links before using an example for a real decision. Existing teaching examples are snapshots, not a current product catalogue or quotation.
  3. Confirm that you have permission to publish the code and content. Decide the repository ownership and licence separately; no licence or public release is implied by this folder.
  4. Upload only reviewed standalone files. The repository's .gitignore allowlist excludes new files by default; review any additions before changing that list. Do not include credentials, local backups or internal documents, or use force-add to bypass the allowlist.
  5. In the repository's Settings > Pages, choose deployment from the publishing branch and its root folder. The .nojekyll file keeps this a plain static site.
  6. Check the deployed project URL, including direct routes such as index.html#inference/request and index.html#sovereignty. Test mobile layout, links and progress storage.

Source and teaching boundaries

Resource cards distinguish courses, documentation and policy sources. Each suggests an outcome rather than completion for its own sake. External sites have their own account requirements, terms, analytics and costs. The site itself embeds no external fonts, scripts, analytics or AI endpoints. GitHub hosts the public site and may process request information under its own privacy policy; local progress is not sent by this application.

Simulations teach relationships; they are not production sizing tools or benchmark results. Legal material is a syllabus and a route to primary sources, not legal advice, a certification or a compliance assessment.

Applied scenarios use invented records, identities, figures and outputs. No source workbook, original data, organisation identity, customer targets, product comparison, private link or reported customer outcome is included in those scenarios. They teach generic patterns rather than documenting a particular engagement. Synthetic examples are not evidence of achieved performance, and removing names alone would not make confidential source material suitable for publication.

Maintaining the site

Topic outlines live in js/topics.js, research and study tasks in js/research.js, inference content in js/learning.js, terms in js/learning-terms.js, lab simulations in js/learning-labs.js, diagram layouts in js/learning-diagram-specs.js and the diagram renderer in js/learning-diagrams.js. The standalone shell uses js/learning-app.js and css/learning-site.css over the original shared styling.

Scenario text, synthetic tables, lesson mappings, decision feedback and flow definitions live in js/scenarios.js. They register their flows with the existing diagram engine. Check that synthetic arithmetic, diagram steps, lesson links, feedback and mobile tables remain consistent when changing a scenario. Scenario answers are not persisted; the inference lesson progress is unchanged.
